# Design System: Solar AI

## Overview

Home is a concise gateway with a conceptual sunlight/home/storage visual, two primary route links and secondary exploration links. Overview reads the current shared state with an explicit Simulator edit link. The visual language remains a daylight control desk: pale green diagram surfaces, forest-green actions, precise values, and an authored vector solar panel and home on the operational pages.

Arabic and English share the same components and state. The retained IBM Plex Sans Arabic family supports continuity with the project; the redesign changes composition and interaction rather than introducing a second identity.

## Colors

The scene field distinguishes the illustrated network from editable white controls. Solid primary fill marks selected scenarios, the suggested destination, and primary actions. Amber belongs to sunlight and lit windows. Existing green, red, and blue status treatments distinguish surplus, shortage, and balance. State is also written in text.

The frontmatter inventories literal values in `src/app/globals.css` and the authored `EnergyFlow.tsx` drawing. Names describe the selectors or SVG materials that use them; the inventory does not imply that every literal is already a CSS custom property. `primary`, `ink`, `muted`, `border`, and `surface` reflect the final root overrides. The `legacy-*` entries record superseded root/brand declarations and the retained old energy-path selector, not the current palette for new components. Focus retains the earlier green independently of the final primary color. Illustration colors are scoped to the drawing.

## Typography

Landing and overview headlines use a 52px display size, stepping to 44px, 38px, and 36px at the implemented breakpoints. Operational headings retain their smaller scale. Body text uses the existing Arabic-capable font stack. Measurements use tabular numerals and explicit LTR fragments; number inputs use Segoe UI and an English language hint. The browser can still localize native numeric glyphs.

Typography entries record actual size roles, including responsive overrides; omitted properties inherit from the relevant selector or body rather than asserting a new font or weight. `legacy-action-status` records the fractional size in the retained `AvailableActions.tsx` component. Its old visual treatment is not guidance for the redesigned routes. The smallest scene-annotation and phone destination-status sizes are descriptive inventory of existing secondary text, not a recommended minimum for new content or an accessibility certification.

## Layout

The page is bounded to 1360px with 28px desktop and 18px phone padding. Home leads from the introduction and two actions to a compact conceptual figure and a two-column link list, stacked on phones. Overview places four metrics above the full-width energy diagram, followed by device state and recommendation/explanation columns. Metrics use two columns on phones. Simulator retains its input/result split, stacking on narrow screens. Navigation collapses at 850px.

## Elevation & Depth

Tonal fields and thin borders separate regions. The vector illustration uses faceted geometry and ground shadows within the drawing. Interface panels have no decorative glow, gradient, glass, or drop shadow.

## Shapes

Buttons and destinations use gently rounded 8px corners. The main studio has 18px corners, reduced to 12px on phones. Secondary operational pages retain the existing compact controls and section separators.

The remaining rounded entries cover compact inputs and badges, the motion toggle, navigation and chat, scene status pills, and circular status dots. They describe actual selector values; shared values do not imply that the components have identical geometry.

## Components

- All simulation controls live in Simulator. The Slider component patches SolarProvider immediately; exact numeric values do not snap to slider steps. Home has no simulation state or editing controls; Overview has no simulation inputs.
- Scenario buttons show selection through solid fill and aria-pressed. Custom edits clear the scenario selection.
- EnergyFlow draws generation, home demand, and the recommended surplus branch. It never animates surplus when the calculated surplus is zero. Destination buttons disclose their meaning; they do not execute hardware actions.
- Overview animates eligible paths and provides a pause/resume button. Reduced motion removes path animation while retaining status and routing. Home is conceptual and static; the detailed simulator uses static paths.
- Recommendations retain local, server-fallback, AI, loading, and error states. Native details elements progressively disclose calculation and hardware explanations.
- Hardware labels describe planned integration. The global header says Simulation mode, never System online.

## Do's and Don'ts

- Keep values, scenarios, language, and decisions in the existing shared provider.
- Use the diagram to explain the current state, not fictional telemetry.
- Retain visible keyboard focus and semantic buttons, inputs, and disclosure controls.
- Keep motion purposeful, optional, and conditional on actual calculated state.
- Do not add fictional savings, connected-device claims, or backend rule changes to support visual effects.
