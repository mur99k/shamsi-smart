## 1. الخلاصة

كل الأقسام الثمانية المطلوبة في لوحة التحكم نُفِّذت وربطت بمصدر بيانات واحد
(`ingestReading`) يستقبل القراءات من **USB (Web Serial)** أو **BLE** أو **السحابة**.
لم يُستخدم أي رقم وهمي: أي قيمة غير مقيسة تظهر «—»، وأي قراءة أقدم من 15 ثانية
تُعرض كـ«قديمة» ولا تُستخدم كحالية.

أُضيف قسم تاسع لم يكن في الطلب: **مؤشرات الدراسة الميدانية** (تكامل Wh، استهلاك ذاتي،
استيراد الذروة) مع **تصدير CSV** — لأن الدراسة تحتاج أرقامًا قابلة للتجميع، لا لقطات شاشة.

## 3. تدفق البيانات

```
ESP32 ─┬─ USB  (Web Serial · 115200 · JSON سطر/قراءة) ─┐
       ├─ BLE  (Nordic UART 6e400001…)                ├─→ ingestReading(reading, source)
       └─ Cloud (POST /api/telemetry ← GET كل 5 ث)     ─┘        │
                                                                 ├─ deviceReading  (آخر قراءة)
                                                                 ├─ history[60]    (للمنحنى)
                                                                 ├─ studyTotals    (تكامل Wh)
                                                                 └─ decisionLog[25] (عند التغيّر)
```

**عقد القراءة** (`src/lib/energy/live.ts`):

```ts
export interface LiveReading {
  solarW: number;             // INA219 0x41
  loadW: number;              // INA219 0x44
  batteryW: number | null;    // INA219 0x40 — موجب = شحن
  batteryV: number | null;
  batteryA: number | null;
  batteryPct: number | null;  // null = لا BMS
  lux: number | null;         // BH1750
  tempC: number | null;       // DHT11
  humidity: number | null;    // DHT11
  relay: "on" | "off" | null; // GPIO 19
}
```

**JSON من الجهاز** (سطر واحد لكل قراءة على USB/BLE):

```json
{"solarProductionW":842,"consumptionW":315,"batteryPowerW":-18,
 "batteryVoltageV":12.64,"batteryCurrentA":-1420,"batteryLevelPercent":64,
 "lightLux":51200,"temperatureC":31.2,"humidityPct":38,"relay":"off"}
```

**منطق القرار** (مبني على القياس، بلا محاكاة مخفية):

```
net = solarW − loadW
net < −5              → عجز: أوقف الحمل غير الأساسي
|net| ≤ 5            → توازن: لا إجراء
net > 5 و البطارية>5 → التخزين يعمل الآن
net > 5 و الريليه on → الفائض يغذّي الحمل
net > 5              → فائض غير موجَّه: اربط البطارية أو شغّل حملًا
```

## 5. قرارات تقنية تخصّك

1. **Tailwind v4 كما طلبتِ.** المشروع كان يحتوي Tailwind لكن المكوّن استخدم أصنافًا مخصّصة؛ أُعيد بناؤه بمُفاعِلات Tailwind مع ربط الألوان بتوكنز المشروع
   (`text-[color:var(--ink)]`)، لا ألوان عشوائية. الأزرار فقط تستخدم الصنف المشترك `.button`
   (تركيز لوحة المفاتيح، حالات التعطيل، تقليل الحركة) بدل تكرار 20 utility في كل زر.
2. **قسم المحاكاة بقي أسفل الصفحة** وموسوم بوضوح «وضع المحاكاة». السبب: اختبارات المشروع
   تعتمد عليه، ويسمح بالعرض لو تعذّر توصيل الجهاز. اللوحة الحية فوقه وهي المصدر الرسمي.
3. **البطارية بلا BMS:** لا نخترع SOC. الحالة تُستنتج من إشارة القدرة (يشحن/يفرّغ)،
   وV/A/P تأتي فقط عبر USB أو BLE.
4. **CSV يترك غير المقيس فارغًا**، لا صفرًا. صحّحنا هذا صراحة لأن الصفر يعني «قيس وكان صفرًا».
5. **مؤشرات الدراسة جلسة حالية** وتُصفَّر بزر؛ الدراسة الحقيقية تحتاج أسابيع + تخزين دائم (KV/DB).

## 8. للتشغيل أمام اللجنة

```powershell
cd solar-app
npm run build
npm run start -- --port 3000     # أو الرابط المنشور
```

1. افتحي `/dashboard` — ستظهر حالة فارغة صريحة (لا أرقام).
2. «اتصال USB» أو «اتصال بلوتوث» → تظهر القراءات الحية.
3. «تشغيل/إيقاف» الريليه → يتغيّر السجل والقرار.
4. «تصدير CSV» بعد دقيقة قياس → ملف يحمل أرقام الجلسة.

**قبل العرض:** استخدمي USB أو البلوتوث من المتصفح. مسار السحابة على Vercel
يخزّن آخر قراءة في ذاكرة الخادم (serverless) وقد لا تصل بين الاستدعاءات.
